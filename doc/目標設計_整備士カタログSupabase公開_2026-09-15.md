# 目標設計: 整備士カタログのSupabase公開

- 対象クライアント: 株式会社PM Agent（RIDE JOB）
- 目標: 適格なハローワーク整備士求人を既存Metaカタログへ全件反映し、求人ごとのRIDE JOB詳細ページと固有画像を公開する
- 完了条件: 公開フィード・Meta取込・整備士商品セットの件数、IDと遷移先、画像一意性、広告設定の不変を実測する
- スコープ外: 広告予算、ターゲティング、配信ステータスの変更。生成AI画像候補APIの実行
- 戻し方: Supabase Storageの直前スナップショットを復元し、Metaを再取得して公開前件数へ戻す

## 外部リソース記録

- サービス: Supabase Storage
- プロジェクト: `job-db` (`urvkgyohtqfxmymaivth`)
- リージョン: `ap-northeast-1`（東京）
- プラン: 有料版（2026-09-15 ユーザー確認）
- バケット: `meta-catalog`（public、作成日 2026-09-15）
- ファイル上限: 50 MiB（生成フィード約15 MiBを格納するため、2026-09-15に10 MiBから変更。読戻しで52428800 bytesを確認）
- 初期ベースライン: 現行フィード4ファイルと`publish-state.json`をVercel Blobから移植済み。公開URLから5ファイルを読み戻し、HTTP 200、サイズ、SHA-256を検証。一次フィードは1,312商品、3,020,898 bytes、SHA-256 `d05e76ac621e04d6cdfd311f0af2babb126e862a56f2dda703902c41ad296062`
- 停止方法: GitHub Actionsのcatalog-feedを停止し、Metaの定期取得を停止する。削除はデータ消失を伴うため別途承認対象

## 実測結果

### 公開前データ検証（2026-09-16 JST）

- ハローワーク全国同期: 45,284件を取得、エラー0件。DBは active 30,148件、removed 26,846件
- 整備士候補: 7,877件（自動車整備士7,859件、バイク整備士18件）
- Meta公開適格な外部求人: 7,720件。市区町村を確定できない157件は住所不備として除外
- 求人詳細: 差分4,000件を取得試行（成功3,990件、取得先終了10件）、DB投入後の全体詳細42,959件。公開対象外部整備士の画像特徴に利用できる詳細は5,645件
- 公開予定フィード: 9,032商品（自社求人1,312件＋外部求人7,720件）、整備士8,586商品
- ID: 9,032件全件一意。外部7,720件はハローワーク求人番号の生IDで、同じIDの`/external-job/hellowork/{id}`へ遷移
- 匿名化: 外部7,720件は公開タイトル・本文・勤務時間から企業名、店舗ブランド、勤務先別名を含み得る原文を外し、構造化済みの職種・地域・雇用形態・給与だけで概要を生成。主要な法人格・店舗ブランドの残存0件
- 画像: 外部求人7,720件すべてに専用パス。求人番号は画像に直接描かず、IDハッシュ由来の非可読な図形パターンと求人特徴で固有化。修正後100件の描画パイロットはJPEGハッシュ重複0件（平均65,313 bytes）で、コンタクトシートも目視確認
- テスト: unit 140件、catalog 63件、TypeScript、lint（0 error）、Next.js production buildが成功

### 確定前レビュー

- 事実確認レビュー: raw求人IDで応募画面へ遷移した場合にサーバー側照合を迂回できる指摘を一次データで確認。raw IDと従来の`hw-` IDを同じ検証経路へ統一し、通知・Meta CAPIの商品IDをraw IDへ正規化するテストを追加
- 抜け漏れ／影響レビュー: 外部整備士の勤務時間原文から企業名が露出し得る指摘を一次データで確認。詳細ページとカタログフィードの双方で自由記述を非公開にし、回帰テストを追加
- 修正後レビュー: 勤務時間の除外が既存自社求人にも及ぶ退行を確認。`catalogOrigin=hellowork`だけ除外するよう修正し、既存求人の勤務時間を維持
- 修正後レビュー: 画像内の求人番号から掲載元を検索しやすい指摘を確認。URL・Meta商品IDはユーザー指定どおり生IDを維持し、画像上の番号だけをIDハッシュ由来の非可読パターンへ変更
- 修正後レビュー: 同期鮮度切れ時に前回比の急減ゲートを迂回できる経路を確認。30時間の鮮度に加えて全行の同期時刻差を5分以内に制限し、古い／部分同期データは公開開始前に必ず中止して直前の検証済みフィードを維持するよう変更
- 修正後レビュー: 既存の非整備士求人まで新しい閲覧イベントを送る退行を確認。商品ID付きの閲覧計測は今回の対象である適格な外部整備士だけに限定
- 修正後レビュー: 補助的な詳細API障害で既存非整備士ページが500になる退行を確認。企業名を照合できない原文は返さず、安全な概要表示へ縮退するテストを追加
- 修正後レビュー: 6時間ごとの既存更新を日次へ落とす退行を確認。既存どおり6時間間隔を維持し、日次全国同期の利用可能時間を30時間に設定
- 修正後レビュー: 一次フィード更新と完了マーカー更新の間で強制終了すると次回も停止する指摘を確認。次回起動時に不整合を検知して直前スナップショットを自動復元し、その回は中止する経路を追加
- 修正後レビュー: Storage復元だけではMeta側が最大3時間古いままになる指摘を確認。復元workflowにMeta即時再取得と検出・反映・無効・商品件数の照合を追加
- 修正後レビュー: 外部詳細URLの固定UTMが広告側url_tagsと重複する指摘を確認。外部商品URLは生IDの詳細パスだけとし、広告帰属UTMはMeta側へ一本化
- 現行Supabaseバケットにベースラインが無いとの指摘は、公開URLから5ファイルを読み戻しHTTP 200・サイズ・SHA-256一致を確認したため不採用
- 最終修正後の独立2観点検査: Critical/Highなし
